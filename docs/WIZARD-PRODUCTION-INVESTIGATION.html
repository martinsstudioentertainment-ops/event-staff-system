5. Root cause analysis

Root cause: The registration wizard was intentionally shipped behind the feature_registration_wizard_v2 feature flag, which remains OFF on production.

  • Phases A.0–A.6 deployed wizard code and assets with flag OFF per the master plan (rollback-safe rollout).
  • Phase A.8 in the roadmap is the planned go-live step: enable flag ON + 24h monitor.
  • A.5 E2E tests validated the submit path (shared by legacy and wizard); they did not require the wizard UI to be visible.
  • Production behaviour is correct per design — not a missing deploy or broken assets.

Not the cause: Missing FTP files (assets return 200), broken index.php branching, or CSS 404s.

6. How to activate the wizard on production

  1. Log in to Admin → Feature flags (super-admin required).
  2. Find feature_registration_wizard_v2 — Registration wizard v2.
  3. Check the box to ON and click Save flags.
  4. Hard-refresh register.olasentra.com (or open in private window).
  5. Verify: data-wizard-mode="1", progress bar “Step 1 of 8”, wizard CSS/JS in page source.

Rollback: uncheck the flag → Save → legacy form restores immediately (no deploy).

Verify script: powershell -File scripts\verify-wizard-production.ps1 (must show 0 FAIL after enable).
