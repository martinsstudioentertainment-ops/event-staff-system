8. Why HTML emails can still show corruption

Approval/access-pass emails send HTML only on the wire (buildEmailMimePayload prefers HTML; plain $text is not attached as multipart). QP encoding is correct. Corruption in HTML view implies the client:

  • Decoded QP to UTF-8 bytes but rendered the HTML document with a legacy single-byte font page, or
  • Showed a generated plain-text snippet (Gmail preview) from bytes without UTF-8 awareness, or
  • User copied text through an intermediate layer that re-encoded

Plain-text-only emails (check-in E07, reminder E05) are the most likely source of the reported 15:00 €" 23:00 because raw E2 80 93 sits in an 8bit body.
