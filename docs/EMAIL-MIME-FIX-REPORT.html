Email MIME Fix — Implementation Report

Generated 6 June 2026 (updated post-approval) · Approved per stakeholder sign-off · Based on docs/EMAIL-MIME-ROOT-CAUSE-REPORT.html · Deployed via deploy.ps1 · Backup storage/backups/pre-deploy-20260606-214115.zip

Status: COMPLETE — MIME verification PASS — Implementation approved and live. Dual-format emails send RFC-compliant multipart/alternative with text/plain (8bit) first and text/html (quoted-printable) second. Plain-text clients no longer receive QP-encoded HTML. Raw <br>/<p> tags, =3D artefacts, and mid-word soft breaks are resolved in plain rendering. HTML clients render clickable links. Production SMTP verification (6 June 2026 20:48 UTC) sent all six template types successfully to info@olasentra.com.

1. Root cause (recap)

buildEmailMimePayload() previously discarded the plain-text body when HTML was present, emitting a single text/html + quoted-printable part. Clients showing that body as plain text exposed raw <br>/<p> tags and mid-word QP splits. Fix: emit both parts in multipart/alternative.
