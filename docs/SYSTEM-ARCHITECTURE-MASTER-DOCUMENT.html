Monolithic PHP application with shared includes/ business layer, three production hosts, and a separate Apply portal subtree. State lives in MySQL; configuration and feature flags in system_settings.

3. Registration system

3.1 Flow

  1. index.php — loads active events, registration forms, wizard shell (flag: feature_registration_wizard_v2)
  2. Client — 8-step wizard JS modules OR legacy single-page + returning-registrant.js
  3. api/registrant-lookup.php — returning user prefill by email
  4. api/registration-options.php — dynamic form → events/roles
  5. submit.php → includes/validation.php → staff-repository.php → staff + staff_registrations
  6. Post-save — notifications.php, Google Sheets sync, PWA push, apply remote sync on approval

4. Returning-user flow

Email entered → registrant-lookup.php → registration-returning-profile.php
    → prefill staff + registered events
    → shift gate (registration-shift-gate.js) if profile incomplete
    → pick event/shift → submit.php (same endpoint as new users)

Wizard mode skips legacy returning-registrant.js when data-wizard-mode="1". Fast-track design documented in RETURNING-USER-FAST-TRACK-DESIGN-REPORT.html (not fully implemented).

9. Email system

Trigger (submit, status change, reminder, access pass)
    → includes/notifications.php or reminders.php or access-pass-email.php
    → includes/mailer.php (multipart/alternative MIME)
    → smtp-mailer.php OR php mail()
Parallel: notification-center.php → app_notifications table
Parallel: pwa-push.php → push_subscriptions

10. Admin system

Auth: includes/auth.php. RBAC: includes/admin-capabilities.php (admin / manager / staff roles). Layout: includes/admin/layout-top.php, sidebar.php. Session idle: 5 min (APP_SESSION_IDLE_TTL).

11. Apply system

Subtree apply/admin/ — own database config, SSO cookie from main admin (includes/apply-sso.php), bridge to main ERP (main-admin-bridge.php). Roles: admin + manager only on apply host.
