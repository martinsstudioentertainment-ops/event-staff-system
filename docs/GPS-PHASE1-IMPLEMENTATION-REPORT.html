GPS Attendance Phase 1 — Implementation Report

Generated 6 June 2026 · Feature flag feature_gps_attendance_v2 (default OFF) · Phase 2+ not started

Status: IMPLEMENTED — pending production verification — Phase 1 foundation is behind feature_gps_attendance_v2. When OFF, legacy 100 m check-in and immediate work-hours behaviour is unchanged. When ON: configurable radius via events.signin_radius_m (default 1000 m), pre-check-in hibernation, auto activation at event start, GPS snapshot at check-in.
Deploy steps before testing: (1) Run deploy.ps1 to upload PHP/JS. (2) Apply migration database/migrate-phase52-gps-attendance-phase1.sql on production (or visit a page that triggers ensureAttendanceGpsPhase1Schema()). (3) Enable feature_gps_attendance_v2 in Admin → Feature flags only when ready to test. (4) Schedule cron/attendance-activate.php every 1–5 minutes on event days.

5. Database changes

ALTER TABLE attendance
  ADD attendance_status VARCHAR(32) NOT NULL DEFAULT 'active',
  ADD activated_at DATETIME NULL,
  ADD check_in_lat DECIMAL(10,7) NULL,
  ADD check_in_lng DECIMAL(10,7) NULL,
  ADD check_in_accuracy_m SMALLINT UNSIGNED NULL,
  ADD check_in_gps_at DATETIME NULL;

Existing rows default to active — no behaviour change until flag ON for new check-ins.

6. Rollback procedure

  1. Set feature_gps_attendance_v2 = 0 in Admin → Feature flags (immediate — no deploy).
  2. Optionally run database/rollback-phase52-gps-attendance-phase1.sql to drop new columns (only if no production data depends on GPS columns).
  3. Redeploy previous code via git/FTP if needed.

8. Cron — auto activation

php cron/attendance-activate.php
# Web: https://admin.olasentra.com/cron/attendance-activate.php?key=REMINDER_CRON_KEY

Activates all pre_checked_in rows whose event start_time has passed. Sets activated_at to event start and initializes work hours.

9. Production verification checklist

Prerequisites

  • Migration applied
  • feature_gps_attendance_v2 enabled
  • Test event with venue Eircode + GPS configured
  • Cron scheduled for activation (or wait and reload sign-in page after start)

Flag OFF (regression)

  • Check-in inside ~100 m succeeds (venue QR flow)
  • Check-in outside ~100 m blocked
  • Work hours appear immediately after check-in

Flag ON

  • Check-in inside 1000 m (or event radius) succeeds
  • Check-in outside radius fails with distance message
  • Pre-check up to 1 h before start → success + hibernation message, no work hours
  • Before start, reload sign-in page → same hibernation message
  • At event start, cron (or page load) activates → attendance_status=active, activated_at set, work hours populated
  • GPS columns populated on venue sign-in (lat/lng/accuracy/timestamp)

Mobile verification

  • iPhone/Android at venue: allow location → email lookup → check in
  • Pre-start: green success alert with hibernation copy
  • Post-start: standard checked-in state

Desktop verification

  • Admin → Feature flags — toggle visible and saves
  • Admin → Event form — radius copy shows 1 km when flag ON
  • Admin → Event sign-in QR — radius text matches event
  • Work hours page — hours only after activation for pre-checked staff

10. Out of scope (Phase 2+)

Continuous GPS monitoring, heartbeats, auto sign-out, GPS history logs, dashboard colour states, payroll recalculation, fraud detection, device fingerprinting.

11. Do not proceed to Phase 2 until

  • All checklist items above pass on production
  • At least one real event day validated with flag ON
  • Stakeholder sign-off recorded
