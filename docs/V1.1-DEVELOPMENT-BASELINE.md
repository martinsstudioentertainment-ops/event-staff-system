## Development rules

1. **Preserve backward compatibility** with v1.0 unless v2.0 explicitly allows breaking changes.
2. **Do not modify stable production modules directly** when a feature can be added as an extension.
3. **Isolate new functionality** in extension directories (see below).
4. **Avoid modifying core** authentication, attendance, registration, deployment, and mobile configuration unless fixing a **verified defect**.

### Preferred extension locations

| Path | Use for |
|------|---------|
| `modules/` | Self-contained domain modules (ERP, library, CRM) |
| `services/` | Reusable business services callable from admin/API |
| `features/` | Feature-flagged additions (UI + backend) |
| `integrations/` | Third-party connectors (webhooks, external APIs) |
| `plugins/` | Optional admin UI plugins and hooks |

See `docs/V1.1-EXTENSION-GUIDE.md` for wiring patterns.

### v1.0 core (protected — extend, do not rewrite)

| Area | Canonical paths |
|------|-----------------|
| Authentication | `includes/staff-google-oauth.php`, `getStaffAuthPolicy()`, `getRegistrationVerifiedEmail()` |
| Registration | `index.php`, `submit.php`, `includes/registration-*` |
| Attendance | `includes/attendance-repository.php`, GPS APIs |
| Mobile API | `api/mobile/`, `includes/mobile/` |
| Deployment | `deploy.ps1`, `scripts/upload-safe-fix-bundle.ps1` |
| Settings / flags | `includes/settings-repository.php`, `includes/feature-flags.php` |
| Health | `admin/system-health.php`, `includes/admin/system-health.php` |

## Change policy

Every change must be classified as **one** of:

| Type | Version bump |
|------|--------------|
| Critical Bug Fix | v1.0.x or v1.1.x |
| Security Update | v1.0.x or v1.1.x |
| Performance Improvement | v1.1.x |
| Feature Addition | v1.1.x |
| UI Improvement | v1.1.x |
| Documentation | Any |
| Refactor | v1.1.x (no behaviour change) |
| Breaking Change | **v2.0 only** |

### Required per change

Use `docs/templates/CHANGE_REQUEST.md`:

- Reason
- Files affected
- Regression risk
- Rollback plan
- Verification checklist

## Feature development checklist

No feature is complete until **all** exist:

- [ ] Backend implementation
- [ ] Frontend implementation
- [ ] API (if exposed)
- [ ] Permissions
- [ ] Validation
- [ ] Logging (`error_log('[EventStaff] …')` — no secrets)
- [ ] Health checks (admin System Health where applicable)
- [ ] Deployment manifest update (`scripts/upload-safe-fix-bundle.ps1` or bundle JSON)
- [ ] Documentation (architecture, API, changelog)
- [ ] Regression tests (manual checklist minimum)

---

## Deployment policy

Every production deployment must include:

1. Updated deployment manifest (file list in bundle script or `scripts/deploy-ui-api-manifest.json`)
2. Updated build number (`storage/version.json`)
3. Updated version file label when releasing (`v1.1.x` when first v1.1 ships)

### Post-deploy verification (blocking)

| Area | Check |
|------|-------|
| Registration | `https://register.olasentra.com/steward` → 200 |
| Authentication | Google / OTP policy per admin settings |
| Attendance | GPS + BIB flow on test event |
| Mobile API | `GET /api/mobile/v1/config` → HTTP 200 |
| Admin dashboard | Login + target page |
| System Health | All critical checks pass |

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\upload-safe-fix-bundle.ps1
curl.exe -s -w "`nHTTP:%{http_code}" "https://register.olasentra.com/api/mobile/v1/config"
```

Deployment is **not complete** until production verification succeeds.

## Testing policy

Before deployment, verify (as applicable to the change):

- Registration wizard
- Google authentication
- Email OTP
- PPS sign-in
- Attendance (manual + GPS)
- QR check-in
- BIB assignment
- Mobile API config + auth
- Android app against production config
- Admin dashboard
- Health dashboard
- Notifications
- Short links (`/steward`, `/dsp`, etc.)

**Any failed verification blocks deployment.**

## Versioning

| Series | Scope |
|--------|-------|
| **v1.0.x** | Bug fixes and security patches on stable baseline only |
| **v1.1.x** | Backward-compatible features and improvements |
