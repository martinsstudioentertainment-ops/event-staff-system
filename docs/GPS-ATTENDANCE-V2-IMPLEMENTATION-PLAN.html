GPS Attendance V2 — Implementation Plan

Generated 7 June 2026 · Approved business requirements · Feature flag: feature_gps_attendance_v2 · Companion docs: GPS-PHASE1-IMPLEMENTATION-REPORT.html, GPS-ATTENDANCE-SYSTEM-DESIGN-REPORT.html

Purpose: This plan maps the final GPS Attendance V2 business requirements to a four-phase delivery sequence. Phase 1 is implemented (foundation). Phases 2–4 are planned only — do not start Phase 2 until Phase 1 is verified on production.

1. Core principle

Attendance is fully GPS-controlled. Staff never manually sign out. The system owns sign-in, activation, monitoring, and automatic sign-out based on GPS, event timing, and attendance rules — all behind feature_gps_attendance_v2.

Staff opens venue sign-in → GPS mandatory gate (permission + coords + accuracy + server geofence) → PRE_CHECKED_IN (hibernated) OR ACTIVE → [Phase 2] continuous heartbeat every 30–60 s → ACTIVE while inside zone | LOCATION_PENDING on GPS issues (2 min grace) → AUTO_SIGNED_OUT (geofence / GPS / permission / verify fail / event end) → Payroll: activated_at → checked_out_at

Heartbeat server logic (authoritative)

  1. Verify flag ON, attendance exists, status in (active, location_pending, pre_checked_in).
  2. Recompute Haversine distance server-side — never trust client distance.
  3. If distance > 1000 m (or event radius): → auto_signed_out, reason left_geofence, set checked_out_at, finalize work hours.
  4. If gps_state ≠ ok or coords invalid: → location_pending; start/continue 2 min grace timer.
  5. If grace expires: → auto_signed_out with mapped reason.
  6. If inside zone + GPS ok while ACTIVE: remain active; clear grace.
  7. Update last_heartbeat_* columns.
  8. Return JSON: status, distance_m, grace_seconds_remaining, message.

8. Geofence rules (authoritative)

ConditionZoneAction
Distance ≤ 1000 mInside event zoneAllow sign-in / maintain ACTIVE
Distance ≥ 1001 mOutside event zoneBlock sign-in; if ACTIVE → AUTO_SIGNED_OUT (left_geofence)

Per-event override via events.signin_radius_m. Server function: isWithinEventVenue($event, $lat, $lng, $pdo) — already exists; extend to heartbeat handler.

9. Security rules

  • No GPS = no sign-in — enforced server-side on every check-in path when flag ON (Phase 1.5).
  • No permission = no attendance — client detects; server rejects missing coords.
  • GPS must stay on during shift — Phase 2 heartbeat + grace enforcement.
  • Heartbeat auth — signed token tied to registration + attendance row; rate limit per IP; CSRF on POST.
  • Admin bypass — supervisor scan check-in should log override reason or be disabled under v2 (ops decision).
