GPS-Based Automatic Event Attendance — Design Report

Generated 7 June 2026 · Production: register.olasentra.com · Planning & impact assessment — not implemented in this deliverable

Executive summary: The platform has one-time geofenced check-in (100 m radius, GPS verified at sign-in only). It does not implement continuous GPS monitoring, pre-checked-in hibernation, automatic activation at event start, automatic sign-out, or live colour-coded attendance status. Moving to the specified 1 km automatic attendance system is a major feature expansion requiring schema changes, a heartbeat API, background jobs, and a new staff monitoring client. Recommended as a phased rollout behind a feature flag.

2.4 Geofence rule (1 km)

  • Within geofence: distance ≤ 1,000 m (inclusive).
  • Outside / auto sign-out: distance ≥ 1,001 m.
  • Server recomputes distance on every heartbeat using event venue_lat / venue_lng (Haversine — already in includes/maps.php).
  • Fix getEventSigninRadiusMeters() to read signin_radius_m with default 1000.

2.5 Staff experience (no manual sign-out)

1. Staff opens check-in link (token) on mobile at venue
2. Browser requests location permission (required)
3. If within 1 km and window open:
   - Before event start → "Pre-Checked In — hours start at [time]"
   - At/after start → "Active — attendance monitoring"
4. Page stays open (or PWA) sending heartbeats every 30s
5. Status updates on screen (colour badge)
6. Auto sign-out messages explain reason; link to status page
7. No "Sign out" button anywhere on attendance UI

3. Anti-fraud (server-authoritative)

ThreatMitigation
GPS spoofing / fake coordsServer distance check; reject accuracy > 200 m; velocity check (impossible jumps between 30 s pings); optional Google Play Integrity / iOS attestation (phase 3)
Browser tamperingHeartbeats signed with session nonce + registration token; rate limit; ignore client-reported distance
Session cloningOne active attendance per registration; new heartbeat from different IP/device flags fraud review
Multiple simultaneous check-insUNIQUE on registration_id (already exists); reject second ACTIVE
Stale tab / background throttlingMark LOCATION_PENDING after 60 s no heartbeat; sign out after 120 s (spec: 2 min verify fail)

Limitation: Browser GPS cannot fully prevent sophisticated spoofing. Server-side rules reduce casual fraud; high-risk events may need native app or hardware verification later.

5. Implementation phases

Phase 1 — Foundation (P0)

  1. Migration: attendance status columns + GPS log table; default radius 1,000 m.
  2. Fix getEventSigninRadiusMeters() to use per-event radius.
  3. Extend recordCheckin() → pre-check vs active based on event start time.
  4. Store check-in coordinates + distance + IP.
  5. Update admin/event-form copy (100 m → 1 km).

Phase 2 — Continuous monitoring (P0)

  1. attendance-monitor.js + api/attendance-heartbeat.php.
  2. Auto sign-out: left geofence, GPS denied, 2 min verify failure.
  3. Work hours: compute from activated_at → checked_out_at only.

Phase 3 — Lifecycle automation (P1)

  1. Cron: activate hibernated at event start; sign out all at event end.
  2. Live dashboard colour states + GPS log viewer in admin.

Phase 4 — Hardening (P2)

  1. Velocity / accuracy fraud rules; admin alerts.
  2. Feature flag feature_gps_attendance_v2 for gradual rollout.
  3. Update scripts/verify-* and payroll export for new hours model.

8. Rollback plan

  1. Disable feature_gps_attendance_v2 → revert to one-time recordCheckin() flow.
  2. Keep new DB columns (nullable) — old code ignores them.
  3. Restore EVENT_SIGNIN_RADIUS_M = 100 if needed via settings override.
  4. Stop cron attendance-lifecycle.php on server crontab.
  5. Payroll: admin can still manually adjust hours_paid via existing work-hours UI.

9. Verification checklist (post-implementation)

  • Pre-check 59 min before start → Yellow, hours = 0.
  • At event start (cron) → Green, activated_at set, hours begin.
  • Simulate 1,001 m → Red, reason left_geofence, timer stopped.
  • Revoke location permission → immediate Red, permission_revoked.
  • No heartbeat 2 min → verify_failed.
  • Event end cron → all active signed out, event_ended.
  • No sign-out button in staff UI.
  • Admin live board shows four colours correctly.
  • GPS log rows for every heartbeat.

10. Recommendation

Proceed in phases behind feature_gps_attendance_v2. Do not flip 1 km continuous monitoring on for all events in one release. Start with Phase 1 (radius + pre-check state + stored coords) on staging, then Phase 2 heartbeat monitoring on a pilot event, then cron automation and dashboard colours. Quick win (can ship independently): Update geofence default to 1,000 m and fix getEventSigninRadiusMeters() to honour events.signin_radius_m — ~3 files, low risk, aligns with spec radius only (no continuous monitoring yet).

Related code entry points: check-in.php, event-sign.php, includes/event-sign-flow.php, assets/js/event-sign-location.js, includes/attendance-repository.php.
