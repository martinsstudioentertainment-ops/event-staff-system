Step 2 Event Selection — Root Cause Report

Generated 6 June 2026 | Production: register.olasentra.com/index.php | Wizard flag feature_registration_wizard_v2 ON

Verdict: RESOLVED — Production verification (scenarios A & B) confirms event cards are selectable, the shift counter updates, and Continue advances when at least one open shift is selected. Root cause was CSS pointer-events lock, not broken event-card JavaScript. Fix deployed 6 June 2026.

1. Reported behaviour

  • Event cards rendered correctly; radio/checkbox visible
  • Clicking card or selector did not select the event
  • “0 shifts selected” unchanged
  • Continue blocked (Step 2 validation requires ≥1 shift)

2. Root cause

The shift picker wrapper #event-selection-wrap shipped with class shift-picker-locked on every registration page. Legacy flow uses registration-shift-gate.js to remove that class once personal details are complete. In wizard mode the gate script exits immediately (data-wizard-mode="1") and never unlocks the wrapper.

registration-compact.css applies pointer-events: none on .shift-picker-locked, which blocks all clicks on cards and inputs inside the wrapper. Event binding in assets/js/events.js (change on event_ids[], updateShiftSelectionSummary) was correct but never fired.
