Returning User Shift Validation — P0 Fix Report

Generated 6 June 2026 · Production: register.olasentra.com · Scope: P0 only · submit.php and DB unchanged

P0 fix deployed. Step 8 and submit now require at least one enabled event_ids[] selection. Returning-user email lookup that clears shift picks redirects to Step 2 with an explicit error. Review no longer shows passive “None selected” when submission would be allowed. Happy-path returning users with a valid open event selection are unchanged.

1. Root cause confirmation

Matches RETURNING-USER-SHIFT-VALIDATION-BUG-REPORT.html:

  • Step 2 event validation ran only when leaving Step 2 — not on Steps 3–8 or submit.
  • Step 3 returning lookup called refreshShiftPicker(), rebuilding cards and dropping disabled/registered selections.
  • validateStep(8) checked consent only.
  • Review rendered “None selected” without blocking submission UX.
