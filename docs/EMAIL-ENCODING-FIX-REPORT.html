Email Encoding Fix — Implementation Report

Generated 6 June 2026 · Scope: ASCII-safe email copy + admin alert P0 fix · Deployed to production · No DB / wizard / Phase B changes

Status: COMPLETE — Email paths now use ASCII - and | instead of en dash, em dash, and middle dot. Website/UI formatters unchanged. Automated verification PASS. Production FTP upload confirmed for all email modules.

1. Problem recap

Production showed 15:00 €" 23:00 — UTF-8 en dash bytes (E2 80 93) misread as Windows-1252. Root cause: formatEventTimeRangeLabel() at events-repository.php:578 used in email bodies without ASCII-safe output.

2. Solution

  • New email-only helpers in includes/email-copy.php wrap UI formatters and normalize punctuation via emailAsciiSafe().
  • All outbound email templates switched to *ForEmail() helpers and ASCII literals in subjects/bodies.
  • buildStaffEmailHtmlFromLines() applies emailAsciiSafe() as a safety net on each line.
  • sendAdminAlertEmail() fixed — passes $pdo and plain + HTML parts to sendEmail().
  • UI functions formatEventTimeRangeLabel(), formatEventLabel(), formatEventLocationLabel() unchanged.

5.3 Production test emails

Live SMTP send from this environment requires admin mailbox credentials (not stored in repo). Recommended manual confirmation on production:

  1. Settings → Email → Send test email — subject should show {site} - Test Email (ASCII hyphen).
  2. Approve a test registration — access pass should show Reporting time: HH:MM - HH:MM and Event | date in HTML.
  3. Trigger check-in notification (if enabled) — plain body Reporting time: 15:00 - 23:00.
  4. New registration with admin alert on — admin inbox receives HTML alert (previously failed silently).

After you run a test approval on production, grep the received email source for E2 80 93 or visible €" — should be absent in time lines.
