Email Rejection Template Audit

Generated 6 June 2026 · Audit only — no fixes implemented · Defect: Registration Not Approved / Rejection email · Production transport: SMTP

Root cause confirmed: The rejection email builds a correct plain-text part and a correct HTML part, but buildEmailMimePayload() sends HTML only as a single text/html body with Content-Transfer-Encoding: quoted-printable. When the recipient client displays that body without decoding quoted-printable and rendering HTML (plain-text view, misidentified MIME, or strict security filter), users see literal <br> / <p> tags, words split at QP soft line breaks, and status URLs as raw text. Not a template copy bug — a MIME architecture bug affecting all buildStaffEmailHtmlFromLines() emails.

6. Quoted-printable encoding analysis

PHP quoted_printable_encode() wraps lines at 76 characters, inserting =\r\n soft line breaks. Correct clients decode these before HTML rendering. Defective display occurs when:

  1. Client shows the HTML part in plain text mode (user setting or mobile “message text”).
  2. Client fails to decode QP before display (some older or strict parsers).
  3. Security gateway strips HTML and forwards raw body.
  4. Client receives single-part HTML but treats as text/plain due to missing/alternate Content-Type handling.

10. Collateral impact (same MIME bug)

Any email calling sendEmail($pdo, $to, $subject, $text, $html) with non-empty HTML is affected — not rejection-only:

  • notifyStaffRegistrationSubmitted() — registration confirmation (E01)
  • sendConsolidatedAccessPassEmail() — approval / access pass (E02) — uses custom HTML but same MIME path
  • sendAdminAlertEmail() — admin alerts (E12)
  • sendEventStaffBroadcast() — staff messaging (E08)
  • notifyRegisteredStaffNewEvent() — new event alert (E09)
  • staff-profile-email.php — profile link emails (E10/E11)

Plain-text-only emails (notifyStaffCheckin(), daily reminders) use sendEmail(..., $body) without HTML — not affected by this specific defect.

11. Root cause summary

  1. Primary: buildEmailMimePayload() sends HTML-only single part; plain-text alternative is built then discarded.
  2. Secondary: HTML body encoded with quoted-printable; clients that do not decode QP before display show mid-word breaks at =\r\n boundaries.
  3. Tertiary: Those same clients render HTML tags literally (<p>, <br>) instead of parsing HTML.
  4. Link symptom: Consequence of (1)+(2)+(3) — <a href> never activated; bare URL from HTML source or truncated QP line shown as text.

Not root cause: Template copy, ASCII encoding fix, subject line, status token generation, or SMTP auth. Rejection-specific wording (“Contractor listed…”, “Sent by…”) merely provides the vocabulary that QP breaks split.

13. Fix directions (audit only — not implemented)

For implementation phase reference only:

  • Emit multipart/alternative with both text/plain; charset=UTF-8 and text/html; charset=UTF-8 parts.
  • Consider 8bit or base64 for HTML on UTF-8 SMTP to reduce QP soft-break surface.
  • Optionally remove duplicate status URL (inline + button) in HTML for cleaner fallback.
  • Re-test rejection email in Gmail, Outlook, and Apple Mail plain-text + HTML views after MIME fix.
