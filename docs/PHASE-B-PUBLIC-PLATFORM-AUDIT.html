Phase B — Public Platform Audit

Generated 6 June 2026 · Audit only — no code changes, no redesign · Production probed live · Screenshots captured before recommendations

Scope: Full public platform review across marketing site, registration entry, mobile experience, navigation, trust, SEO, conversion, accessibility, performance, branding, and four-domain architecture. Phase A (registration wizard) and email encoding fixes are accepted prerequisites. This document inventories current state and prioritizes Phase B implementation work — it does not prescribe a redesign.

1. Executive summary

The public platform is functionally complete for its core job: marketing pages explain the model, registration wizard converts on register.olasentra.com, and staff PWA exists. The premium homepage (~70% of UX Master Plan vision) is credible and data-driven. The largest gaps are visual/theme inconsistency (dark premium home vs light inner pages), SEO canonical misconfiguration (marketing pages canonicalize to register subdomain), missing About page, and brand/name drift (production site name “Security Update” vs Olasentra positioning in docs).

5. Area-by-area audit

5.1 Homepage Strong

  • Premium dark theme live (feature_public_premium_v2); hero, live events grid, animated stats, trust chips, testimonials, staff portal band, final CTA.
  • Live data from DB: open events count, registrations this week, approved staff.
  • Hero aside logo card consumes prime fold space (conversion risk — see B-H1).
  • Stats animate from SSR values in production screenshot (numbers populated after JS); prior audit noted flash-of-zero risk when DB empty.
  • Hero lead copy on production mentions “steward” jobs; site notice says stewarding not listed — copy tension.

5.2 Events page Partial

  • events-page.php is CMS educational content (event types, 4-step flow) — not a live events directory.
  • Homepage live grid is the real event discovery surface; events page does not mirror it.
  • No deep links from category tiles on home to events page anchors.
  • CTA band points to registration — good conversion exit.

5.3 About page Missing

  • No about.php; UX Master Plan and Implementation Master Plan list it as planned.
  • how-it-works.php partially covers company story via getCompanyTrustPoints().
  • No dedicated team, mission, or “who operates this portal” narrative beyond notice bar and FAQ.

5.4 Contact page Adequate

  • Email, phone, WhatsApp, hours from CMS; contact cards with clear hierarchy.
  • No contact form (email/tel links only) — reduces spam risk but adds friction for some users.
  • Same light theme and shared nav as other inner pages.

5.5 FAQ page Adequate

  • Native <details> accordion — accessible pattern, no JS required.
  • 6 CMS questions; covers pay model, duplicates, approval — aligned with employer-wording audit.
  • Slim CTA band links to contact and registration.
  • Could expand: PSA licence requirements, check-in process, data retention.

5.6 Registration entry points Strong

  • Primary: header Register CTA, hero CTA, live event cards, footer Register, roles page per-form links, FAQ/contact CTA bands.
  • All resolve to register.olasentra.com wizard (verified in HTML probe: 13–28 register mentions per page).
  • Deep links: index.php?form={slug} for role-locked forms.
  • Secondary: staff-portal, staff-app, status.php for returning users.
  • Visual jump: premium/light marketing → wizard dark compact — related but not unified token set.

5.7 Mobile experience Good

  • mobile.css (13 KB) + responsive header hamburger (website.js).
  • Registration wizard mobile QA completed in Phase A.7 — strong touch targets, progress bar, autosave indicator.
  • Homepage mobile screenshot: hero stacks cleanly; notice bar scrolls; CTAs reachable.
  • Inner pages: functional but less polished than wizard; FAQ accordion works on small screens.
  • No homepage PWA install prompt; staff-app promotion absent on marketing site.

5.8 Public navigation Consistent

  • Header: Home, Roles, Events, How it works, FAQ, Contact + Register CTA (getWebsiteNavItems()).
  • Footer: Explore column, Apply column, Contact column, bar links (registration, privacy, admin).
  • Active state on current page; mobile menu toggle with aria-expanded.
  • Missing About nav item; privacy only in footer bar not header.
  • Premium nav styling not applied — header looks pre-premium on all pages including home.

5.9 Trust signals Good with gaps

  • Site notice bar: employer model disclaimer, PSA focus, free portal — strong compliance copy.
  • Homepage trust chips, compliance list, testimonials (hardcoded), live registration counts.
  • Wizard trust row: free, mobile friendly, secure storage, platform note.
  • Gaps: privacy page uses different visual system and states “process payroll” (may overstate portal role); no physical address on contact; testimonials not CMS-editable; production brand name “Security Update” undermines credibility.

5.10 SEO foundations Weak

  • Per-page <title> and meta description via renderShareMeta() — present on marketing + register.
  • OG image via og-image.php or branding logo — good for social.
  • Critical: canonical + og:url use register.olasentra.com for pages served on olasentra.com.
  • No JSON-LD (Organization, WebSite, Event).
  • No robots.txt or sitemap.
  • Privacy page: no OG, no canonical, no description.
  • DirectoryIndex home.php — root may serve home without redirect canonicalization to /home.php.

5.11 Conversion funnel Friction points

  1. Awareness: Home hero + organic — premium look builds interest.
  2. Consideration: Roles, How, FAQ, Events — light pages; theme drop may reduce confidence.
  3. Intent: Register CTA ubiquitous — good.
  4. Action: Wizard Step 1 — strong (Phase A); autosave, time estimate, open event count.
  5. Friction: Hero aside distracts; no urgency on event cards; no “resume application” on homepage; brand name confusion; events page doesn’t show live openings.

5.12 Accessibility Baseline

  • lang="en" on html; nav aria-label; menu button aria-label; notice role="region".
  • FAQ uses native details/summary — keyboard accessible.
  • Wizard: progressbar ARIA, live regions for save status (Phase A).
  • Gaps: privacy page minimal semantics; focus ring consistency unknown on premium buttons; color contrast on mint FAQ section untested; no skip-to-main link; decorative SVGs mostly aria-hidden on home.

5.13 Performance Acceptable

  • CSS payloads moderate (21 KB website + 19 KB premium on home; wizard 19 KB on register).
  • Google Fonts (Inter) loaded only on premium home — extra round trip.
  • home-premium.js for counter animation — non-blocking at end of body.
  • No evidence of image lazy-loading on homepage; QR/external images on emails not relevant here.
  • Single shared hosting — no CDN; acceptable for current scale.

5.14 Branding consistency Split

  • Logo renders in header/footer; theme color from settings.
  • Three visual systems: (1) premium dark home, (2) light marketing inner, (3) wizard/staff compact dark.
  • Production site name “Security Update” vs “Olasentra” in documentation and wizard platform note.
  • Privacy page: legacy login-page card — breaks brand continuity.
  • Inter font home-only; inner pages use system stack.

8. Recommendations (post-inventory — no implementation in this phase)

Quick wins

  • B-QW1: Fix canonical/OG URL to use getMarketingSiteUrl() on marketing pages; keep register URL only on register host.
  • B-QW2: Restore production site name to intended public brand (Admin → Settings → Site name).
  • B-QW3: Align hero lead copy with PSA-only notice — remove “steward” if not offered.
  • B-QW4: Add meta description + OG tags to privacy.php; wrap in marketing shell or match footer link style.
  • B-QW5: Add “Resume registration” link on homepage staff portal band (wizard autosave exists).
  • B-QW6: Add robots.txt allowing marketing + register; disallow /admin/, /cron/, apply host.

Medium improvements

  • B-M1: Extend premium theme (or shared dark shell) to Roles, Events, How, FAQ, Contact — single feature_public_premium_v2 scope expansion.
  • B-M2: Replace hero aside logo card with urgency module (open events, closing shifts).
  • B-M3: SSR final stat values in homepage HTML; animate as progressive enhancement.
  • B-M4: Create about.php CMS page — mission, operator model, link from nav/footer.
  • B-M5: Events page: embed live open-events strip from getHomepageLiveData() or link to home anchor.
  • B-M6: Move testimonials to CMS (admin/website-home.php or new section).
  • B-M7: Add Organization + WebSite JSON-LD on home; FAQPage schema on FAQ.
  • B-M8: Premium header/nav styling when premium theme active.
  • B-M9: Homepage PWA band — “Add to home screen” linking to staff-app + manifest.
  • B-M10: Privacy page rewrite for employer-model accuracy; unified layout.

Major redesign opportunities

  • B-X1: Unified public design system — shared tokens across marketing, wizard, staff-app (UX Master Plan “Event Operations” DNA without ERP chrome on public surfaces).
  • B-X2: Live events as first-class public directory — searchable/filterable events page backed by DB, not CMS taxonomy only.
  • B-X3: Full marketing information architecture — About, Careers, For organisers, Case studies (if B2B expansion).
  • B-X4: Marketing site static generation or edge cache layer for home stats/events (performance + SEO).
  • B-X5: Cross-domain analytics dashboard — funnel from olasentra.com CTA → wizard step completion (wire registration-analytics to marketing events).
