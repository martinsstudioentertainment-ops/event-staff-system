2. Data Model → UX Domains

The database implies six product domains. UX should mirror these, not the current 22 flat sidebar links.

DomainCore tablesNatural UX home
Peoplestaff, staff_registrations, staff_blacklistStaff Directory + Registration Queue
Events & venuesevents, venues, work_typesEvent Command Center
Field opsattendance (+ work-hours columns)Live Ops (check-in, hours)
Communicationsstaff_messages, app_notifications, push_subscriptionsUnified Inbox
Financecommission_invoices, saved_job_records, personal_invoice_linesFinance workspace
Platformsystem_settings, admin_users, admin_audit_log, website_visitsSettings & governance

Key entity relationships

  • staff = identity (one person, one email)
  • staff_registrations = shift application (one row per email × event)
  • attendance = check-in record (one per registration)
  • staff_messages = threaded by staff_id, not registration
  • app_notifications = dual audience (admin | staff), keyed by staff_email for staff
Design rule: Staff screens anchor on person (email/session). Admin screens support context switching between person view and event view.

ZoneContent
Primary CTA"Review N pending" OR "Open Live Ops" on event day
KPIsPending · Approved today · Check-ins today · Unread inbox
Attention queue① Pending ② Unread messages ③ Ops checklist ④ PSA expiring

Staff role (venue operator)

ZoneContent
Primary CTAStart scanning → scan-checkin.php
KPIsCheck-ins today · On-site now · Remaining approved
Attention queueEvent selector (today's events only)
Quick actionsScan · Attendance log · Work hours

Dashboard rules

  1. One primary CTA — never 4 competing buttons
  2. Attention queue is prioritized, not a flat card grid
  3. Event-day mode auto-surfaces Live Ops when event is within ±2 hours
  4. Drill-down only — dashboard never edits data inline

12. Critical User Journeys

A — New staff registration

Marketing home → Register → index.php → submit.php
  → email → status.php?token= (pending)
  → [admin approves] → notification + email
  → status.php (approved) → staff-app.php → install PWA

B — Event day operations

Command Center → "Live Ops" CTA
  → scan-checkin.php → attendance.php (exceptions)
  → work-hours.php → export-attendance.php

C — Pre-event readiness

ops-checklist.php → pending_cleared → staff.php
  → apply_sync → apply-portal.php
  → psa_expiry → Apply PSA compliance
  → sheets_spot_check → google-sheets-diagnostic.php

D — Finance month-end

invoices.php → invoice-quick.php → print-invoice.php
  → job-records.php → export-invoices-month.php

14. Design Principles

  1. Ops-first, finance-second — Daily users live in Operations + People
  2. Event context is king — Global event selector in admin header
  3. Mobile-native staff, desktop-native admin
  4. One badge per channel — Unified inbox badge only
  5. Progressive disclosure — System/CMS hidden until needed
  6. Keep premium sidebar — Regroup items into 6 modules, don't redesign chrome
